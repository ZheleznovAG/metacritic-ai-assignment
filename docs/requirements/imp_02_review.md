# IMP-02: one real multiplatform game, end-to-end

Date: 2026-09-11 (UTC). Task `IMP-02`; requirements `DATA-01`, `DATA-02`, `DATA-03`, `UI-02` (partial: card only, list UI is `IMP-05`), `NFR-04`; risks `R-ID-01`, `R-DAT-01`, `R-EXT-03`, `R-EXT-04`. Current status belongs to [action_plan.md](../../action_plan.md).

## Scope actually built

`catalog` app (`Game`, `GameAlias`, `GamePlatform`, `SourceFetch`), a plain `metacritic` package (typed DTOs, pure HTML/SSR parser, bounded-fan-out HTTP gateway), minimal `processing` (`DailyCycle`, `DailyCandidate`, `Clock` protocol) and `reviews` (`ReviewCollectionJob` placeholder) apps, a non-destructive `catalog.ingest.ingest_game` orchestration in one `transaction.atomic()` block, a `catalog/management/commands/ingest_game.py` one-off entry point (`scripts/ingest_game.py` wrapper), and a read-only public card at `GET /games/<id>/`.

Explicitly deferred to later tasks (see the plan's scope boundary): `SEL-01–03` batch/day-cycle selection, `processing_lease`/`core_attempt` fencing and scheduler/worker processes (`IMP-03`), review pagination/collection and AI summaries (`IMP-04`), the game list UI — search/filter/sort (`IMP-05`/`UI-01/03/04/05`), retry/backoff policy (`HRD-01`), and a dedicated worker DB role (`scripts/ingest_game.py` currently reuses the schema-owner `MIGRATE_DB_USER` role, documented in its docstring as a known temporary simplification).

## First adversarial round: self-review (`/code-review high`)

| Finding / counterexample | Correction / verification |
|---|---|
| `_upsert_platform`'s update branch never re-synced `source_game_platform_id` when a new, unclaimed value arrived — the stored assertion could silently drift from the source forever even with no conflict | Added the reassignment (`app/catalog/ingest.py`); added `test_an_unclaimed_new_platform_assertion_id_is_synced_on_update` to lock in the behaviour |
| A naming collision between two loop variables in `ingest_game` (`platform` reused for both the DTO loop and the model loop) was silently harmless at runtime but mypy correctly flagged the type conflict | Renamed the first loop's variable; `mypy --strict` is clean |
| bs4-stubs' attrs-only `find`/`find_all` overloads are stricter than the runtime signature | Isolated the workaround in small, documented helpers rather than scattering `type: ignore` across the file |
| A missing `relatedGameId` on a platform record was silently stored as an empty-string placeholder, which would collide across platforms sharing the same missing value | `_parse_platform` now raises `MetacriticParseError` instead (a mandatory identity assertion per `SPK-03`, not an optional field) |
| `user_reviews_path` was derived with a bare `.replace("critic-reviews", "user-reviews")`, silently producing a wrong URL if the substring were ever absent | Only derive it when the marker is actually present; added `test_user_reviews_path_is_not_derived_without_a_known_marker` |
| `cover_url`/`video_embed_url`/`video_content_url` were rendered into `href`/`src` with no scheme check — a `javascript:`-scheme value from the scraped page would execute on click | Added `_safe_url` (http/https only); added `SafeUrlTests` |

## Second adversarial round: an unprompted peer session's independent verification

While the fixes above were still being applied, a separate Claude Code session working on the same repository (`metacritic-ai-assignment-dc`) independently re-read the on-disk code against a pasted adversarial-review report and reported its own findings back to this session, noting two of the report's claims no longer reproduced (the fix above) and five other findings that did. Each was verified against the real site before fixing, not just accepted on the report's word:

| Finding | Independent verification | Correction |
|---|---|---|
| `_merge_field` only guarded against `None`, not a blank/whitespace-only string, so an empty scraped field could overwrite a previously-known good value | N/A — logic inspection | Blank strings are now treated the same as `None` in `_merge_field` (numeric falsy values like a real `0` are untouched, since the check is `isinstance(new, str)`-scoped); added `test_a_later_blank_string_does_not_clobber_a_previously_known_value` |
| `_find_game_record` returned the *first* `"game-title"`-shaped record in the payload with no check that it was *this* page's record — a "similar games" widget could carry another such record | Confirmed the game's own record exposes a `slug` field distinct from any carousel item; on the actual Elden Ring capture only one such record exists today, so this was a latent risk, not an observed failure | `_find_game_record` now requires the resolved `slug` to match the requested page's slug; raises otherwise; added `FindGameRecordTests` with a synthetic two-record payload |
| Neither `fetch_game` nor `fetch_platform_userscore` checked that the returned page actually corresponds to the requested URL | Live-fetched the real Xbox One user-reviews page and confirmed it carries `<link rel="canonical">` and `<meta property="og:url">` matching the exact requested URL (including the `?platform=` query) | Both parser entry points now take the requested URL and reject a page whose canonical/`og:url` doesn't match (`_require_matching_canonical`); all six fixtures were rebuilt to include the tag; added `test_mismatched_canonical_url_raises` and `test_mismatched_platform_page_raises` |
| Degraded extraction (container present but broken, e.g. a future markup change) is indistinguishable from a genuinely empty score — both report `outcome=succeeded`, `metascore=None`/`userscore=None` with no signal | Logic inspection; not fixed | **Documented limitation, not blocking**: this is the same class of gap `HRD-01`'s failure-fixture work is scoped to close; not fixed in `IMP-02` |
| A fanned-out platform's Userscore fetch (`SourceFetch(kind="platform_userscore")`) was saved but discarded — every platform's `last_changed_fetch` FK was set to the `game_detail` fetch regardless, losing per-platform fetch provenance | N/A — logic inspection | `ingest_game` now tracks a `{source_platform_id: SourceFetch}` map for fanned-out platforms and attributes `last_changed_fetch` correctly; added `test_a_fanned_out_platforms_provenance_points_at_its_own_fetch` and confirmed live (see above) |

A bug in the *test* helper surfaced while verifying the provenance fix: the shared `_evidence()` builder in `test_catalog_ingest.py` hardcoded `kind="game_detail"` regardless of caller, so `FakeGateway.fetch_platform_userscore` was mislabelling its own evidence — caught immediately by the new test (`MultipleObjectsReturned`) and fixed by parameterising `kind`.

A DB-level race was also closed proactively while addressing the above (not itself a reported finding): `_ensure_candidate` now takes `select_for_update()` on the `DailyCycle` row before computing the next `source_order`, so two ingests racing on the same business date inside their own `transaction.atomic()` block cannot both compute the same `source_order` and hit `IntegrityError`. Full scheduler-grade lease/fencing across cycles remains `IMP-03`.

This is no longer solely a self-review: an independent session verified the code, and every finding it confirmed as still-reproducing was fixed and covered by a new test, with the highest-risk one (canonical-URL/misroute) additionally confirmed against the live site. The `IMP-01`-style caveat ("this is an adversarial self-review, not an independent person's review") no longer applies unmodified to `IMP-02`.
