## Adversarial review вывода

- Первую ошибку sandbox нельзя выдавать за неисправность VDS: проверка повторена с разрешённым SSH-доступом за пределами sandbox.
- TCP connect не доказывает работоспособность SSH-сервиса: remote banner отсутствует.
- Нельзя заключать, что ключ неверен или отозван: до предложения ключа дело не дошло.
- Нельзя заключать, что Docker отсутствует или deploy-user не имеет прав: соответствующая удалённая команда не выполнялась.
- Точная причина закрытия соединения не установлена. Это может требовать проверки SSH-службы или сетевых ограничений со стороны владельца; конкретная причина без server-side evidence не назначается.
- Подтверждённые ранее возможности SPK-06 остаются историческими фактами, но не заменяют текущий доступ.

## Ask и условие продолжения

**Ask:** восстановить ранее согласованный SSH-доступ к VDS и подтвердить, что можно повторить preflight. **Needed-by: G4**, до раннего deploy в IMP-01, согласно [ADR-0001](../decisions/0001-minimal-stack-and-architecture.md).

После восстановления повторить ту же read-only проверку Engine/Compose и прав текущего deploy-user. Только после подтверждения требуемых capabilities продолжать зависимый deployment; отсутствующий Docker/Compose потребует отдельного решения, а не обхода через ad-hoc процессы.

Приложение, CI и image этим preflight не созданы; задача не Verified. VDS, firewall, SSH configuration, system packages, probe и существующие контейнеры не менялись. Следующие задачи не начинались. Независимые eval-oracles доступны по графу, но требуют отдельных task cycles.

## Повторная проверка после настройки владельцем

Владелец сообщил о восстановлении SSH, создании пользователя `<deploy-user>`, настройке Docker и замене переменных на `DEPLOY_SSH_*`. Повторный read-only preflight с этими переменными прошёл: SSH exit `0`, Docker Engine `29.1.3`, Compose `2.40.3+ds1-0ubuntu1~24.04.1`, доступ к daemon есть. Non-interactive sudo отсутствует, но для принятого Compose deployment не требуется. Старый probe `/health` на loopback:18080 не ответил успешно; его процессы/config не изменялись, текущее публичное приложение этим ещё не проверено.

SSH Ask снят. Локальный `git remote` не содержит remote: новый **Ask** — адрес разрешённого удалённого репозитория для push и CI, **needed-by G4**. До ответа не создавать внешние репозитории и не отправлять изменения; локальные scaffold/build/test части IMP-01 независимы от этого входа. Настройка CI без фактического прогона не закрывает exit criterion.
