# SIM-EVAL-01: критерии похожести до выбора метода

Дата подготовки: 2026-09-14 UTC. Связь: `SIM-01–SIM-03`, `AC-SIM-01/03`,
`ASM-20/21`, `R-SIM-01`. Текущее решение владельца и статус задачи — только
в [action_plan.md](../../action_plan.md). Needed-by: `G4`, до `IMP-06`.

## Конкретный предмет решения

[Набор 1.0.0](../../evals/similarity/cases.json) содержит 14 синтетических
сценариев и 52 записи в отдельных небольших каталогах. Каждый кандидат размечен
до реализации similarity: 2 — очевидно близкая игра по известному игровому жанру,
1 — более широкая допустимая связь, 0 — явное несовпадение или отсутствие
положительных данных о связи. К каждому label приложено объяснение.

[Метрика 1.0.0](../../evals/similarity/metric.md): среднее `nDCG@5 >= 0.90`
по девяти положительным сценариям и `>= 0.80` в каждом из них; все восемь
жёстких инвариантов обязательны. Пять пустых/отрицательных сценариев не повышают
среднее. Отсутствующие полезные результаты снижают оценку; заполнять пять мест
нерелевантными играми нельзя. Порог является предложением для принятия,
а не измеренной оценкой предпочтений пользователей.

Проверяются жанровые пары, сильная и более широкая связь, разные платформы,
неполные поля, один разработчик с разными жанрами, совпавшие названия при разных
ID, Unicode, нормализация регистра/пробелов, семь равнозначных кандидатов,
только текущая игра, пустая база, отсутствующий query ID и отсутствие всех
признаков. Сортировка равнозначных результатов не задана конкретной формулой,
но должна точно повторяться при неизменном каталоге и перестановке входа.

[Manifest](../../evals/similarity/manifest.json) фиксирует byte hashes набора,
метрики, контракта и evaluator. `IMP-06` получит только сохранённые признаки,
без labels; actual method и более простой baseline ещё не реализованы и
не сравнивались. Reference answer в тестах намеренно читает labels только как
test double для проверки арифметики и отказов evaluator.

## Проверка и adversarial review

Независимая проверка — [14 meta-tests](../../evals/similarity/test_score_similarity.py):
ручной расчёт DCG, пропущенные результаты, per-case floor при проходящем среднем,
self/external/duplicate/over-cap/non-match/bool outputs, исключение вместо ответа,
зависимость от порядка или предыдущего вызова, изменение входа, нарушение только
на последующих перестановках, missing query, полнота judgments и изменение одного
байта frozen dataset. Все 14 пройдены локально на Python 3.12.

Review проверил, что empty output не проходит только за счёт правильных
исключений, negative cases не раздувают среднее, duplicate не получает повторный
gain, quality проверяется для каждой перестановки, а одинаковый title не служит
identity. Жанровые labels и пороги не выведены из candidate `0.1.0`.

Обнаруженное ограничение интеграции: источник genre подтверждён в `SPK-02`,
но текущий `catalog.Game` его пока не сохраняет. `IMP-06` должен добавить
проверенный DTO/storage путь для используемых признаков до production ranking;
получать незаметно признаки через live HTTP внутри ranking нельзя. Этот oracle
не утверждает, что такой путь уже реализован.

Малый synthetic set не доказывает предпочтения реальных пользователей,
семантическую близость при разных словарях или production capacity. Проверки
карточки, правильного ID перехода и реального каталога относятся к `SIM-VER-01`.
Тексты и названия вымышлены; live Metacritic/AI для этого решения не нужны.

```powershell
.\.venv-app\Scripts\python.exe -B evals/similarity/score_similarity.py --verify
.\.venv-app\Scripts\python.exe -B -m unittest discover -s evals/similarity -p "test_*.py" -v
```

Оба checks включены в `scripts/check.py` и checks image для воспроизводимого CI.
Полный local `scripts/check.py` пройден: format/lint/mypy, migration drift,
263 application tests на PostgreSQL 16, scripts 6, planning 18, AI integrity 7,
review selection 9 и similarity oracle 14 tests; frozen/candidate verifiers PASS.
Hosted run и его SHA записываются после фактического выполнения.

## Ask владельцу

Принять oracle 1.0.0: 14 сценариев, `nDCG@5 >= 0.90` в среднем и `>= 0.80`
в каждом положительном сценарии, максимум пять уникальных сохранённых игр без
self-match и явных grade-0 несовпадений?

Это явный выходной критерий [SIM-EVAL-01](../../implementation_plan.md#sim-eval-01),
а не разрешение на обычную реализацию. До ответа comparison и выбор policy
не начинаются; независимая проверка scheduler и review/UI контуров продолжается.

**Ответ владельца (2026-09-14):** oracle 1.0.0 принят как есть, без изменений
набора, метрики или порогов. `SIM-EVAL-01` закрыт этим решением; `IMP-06`
разблокирован по этой зависимости (dependency `IMP-02` уже выполнена).
