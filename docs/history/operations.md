- Эксплуатационная находка, 2026-09-25 (публичный сервис `bonus2`, вне G-ворот): игра «Xevious 3D/G» (`catalog_game.id=1218`, локатор `/game/xevious-3d-g/`) стабильно и повторяемо (24.09 и 25.09, все 5 автоматических попыток каждый раз) даёт `IdentityConflict` при почасовой обработке. Причина — у самого Metacritic страница списка New Releases и страница карточки для этого одного URL постоянно расходятся: список отдаёт `source_game_id=1300015335`/«Xevious 3D/G», карточка — другой ID `1300002384`/«Xevious 3D/G+». Защита от identity-конфликтов (`docs/design.md`) корректно отказывается писать вместо слияния двух разных записей. Ручная правка сохранённого ID не устраняет причину: при следующем обнаружении список снова даст старое значение, и конфликт просто переместится с этапа карточки на этап обнаружения. Решение владельца, пересмотрено: точечный список исключённых locator'ов в discovery (`processing/selector.py: EXCLUDED_LOCATORS`), проверяется в обеих фазах (New Releases и browse) до создания кандидата — по locator, а не по `source_game_id`, потому что именно он у источника нестабилен. Правка identity/базы не годится: `resolve_game_identity` при обнаружении вызывает ту же `_resolve_game`, что и загрузка карточки, так что смена сохранённого ID лишь переносит тот же `IdentityConflict` с этапа карточки на этап обнаружения, не устраняя его. Проверка: 2 новых теста (`test_processing_selector.py::ExcludedLocatorTests`, обе фазы), полный набор — 475 тестов приложения, ruff, mypy. Снятие записи из списка — отдельное решение владельца, автоматической проверки актуальности источника нет. Gate-статусы не менялись.
