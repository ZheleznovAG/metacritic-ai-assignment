Для выполнения этого задания необходим гибкий итеративный инженерный процесс с упором на надёжный сбор данных, управление LLM-компонентами и наблюдаемость. Ниже перечислены ключевые этапы и практики, **без проектирования конкретного решения**.

## 1. Анализ и декомпозиция требований

- Изучить структуру Metacritic: разделы New Releases и SEE ALL, пагинацию, форматы страниц игры, отзывов.
- Проверить `robots.txt`, условия использования, допустимую частоту запросов.
- Определить модель данных: игра, платформа, оценки, обложка, разработчик, описание, видео, резюме критиков/пользователей, похожие игры.
- Разбить работу на независимые этапы:
  - сбор и парсинг;
  - хранение и обновление;
  - генерация резюме (LLM);
  - веб-интерфейс (список, карточка, фильтры, поиск, сортировка);
  - подбор похожих игр;
  - дополнительные части (YouTube-летсплеи, мониторинг).

## 2. Управление задачами и итеративная разработка

- Использовать Agile-подход (Kanban или короткие спринты).
- Вести бэклог задач с критериями готовности (Definition of Done).
- Регулярно демонстрировать рабочие инкременты (например, сначала CLI-сбор, затем API, затем UI).
- Фиксировать все взаимодействия с ИИ-ассистентом (JSONL-логи) — это часть результата.

## 3. Контроль версий и совместная работа

- Git, стратегия ветвления (feature branches).
- Обязательные code review.
- Семантические версии и понятные сообщения коммитов.
- Хранить в репозитории:
  - код;
  - миграции БД;
  - примеры конфигураций;
  - промпты и их версии;
  - сырые сэмплы HTML/JSON для тестов.

## 4. Тестирование

- **Юнит-тесты** для парсеров, моделей, утилит преобразования данных.
- **Интеграционные тесты** на основе сохранённых фикстур реальных страниц (без живых запросов).
- **Тесты устойчивости**:
  - повторные попытки при сетевых сбоях;
  - обработка изменений вёрстки;
  - таймауты и ограничение частоты.
- **E2E-тесты** веб-интерфейса (поиск, фильтры, переходы).
- **Валидация LLM-выходов**:
  - проверка JSON-схемы;
  - ограничение длины и формата;
  - ручная выборочная проверка качества резюме.
- **Тесты идемпотентности**: повторный запуск обхода не должен создавать дубликаты или портить данные.

## 5. CI/CD и окружения

- Автоматический запуск линтеров, тестов, сборки на каждый push/PR.
- Контейнеризация для воспроизводимости (Docker).
- Автоматические миграции БД.
- Деплой на staging и production.
- Хранение секретов (API-ключи, доступы к БД) в защищённом хранилище.

## 6. Наблюдаемость и мониторинг

- Структурированные логи с контекстом (источник, страница, игра, этап).
- Метрики:
  - количество обработанных игр за прогон;
  - длительность каждого этапа;
  - число успешных/провальных запросов;
  - статусы воркеров (если используется очередь задач).
- Алерты при повторяющихся ошибках или превышении лимитов.
- Для дополнительной части 2 — дашборд в реальном времени и кнопка ручного запуска.

## 7. Работа с веб-скрапингом

- Уважение к `robots.txt` и разумная частота запросов.
- Кэширование HTTP-ответов для отладки и снижения нагрузки.
- Ротация User-Agent, при необходимости — прокси.
- Сохранение сырых HTML в лог/хранилище для последующего анализа ошибок.
- Планировщик (cron или аналог) с гарантией однократного выполнения в час.

## 8. Управление LLM-компонентами

- Версионирование промптов и результатов.
- Кэширование ответов LLM для снижения стоимости и ускорения повторных обновлений.
- Отдельные пайплайны:
  - резюме по отзывам критиков;
  - резюме по отзывам пользователей;
  - транскрибация YouTube-летсплея и заключение по тексту (доп. часть 1).
- Контроль токсичности/неприемлемого контента в генерируемых текстах.
- Возможность повторного запуска генерации для отдельной игры без пересбора всех данных.

## 9. Работа с данными и БД

- Версионирование схемы (миграции).
- Транзакции при обновлении игры и связанных сущностей.
- Индексы для быстрого поиска по названию, фильтрации по платформам, сортировки по рейтингу.
- Стратегия обновления: если игра уже есть — обновить изменяемые поля (оценки, резюме), сохранить историю изменений при необходимости.
- Поиск похожих игр: предвычислять или пересчитывать при каждом добавлении новой партии.

## 10. Безопасность

- Защита админ-интерфейса мониторинга.
- Валидация и экранирование пользовательского ввода.
- Хранение API-ключей вне кода.
- Ограничение доступа к внутренним метрикам.

## 11. Документация

- README: локальный запуск, переменные окружения, расписание, архитектура.
- Описание модели данных и связей.
- Инструкция по ручному запуску обработки.
- Чейнджлог изменений.

## 12. Сопровождение и эволюция

- Мониторинг изменений на Metacritic/YouTube и быстрое реагирование.
- Возможность отката миграций и данных.
- Регулярное ревью промптов и качества резюме.
- План по обработке отказов внешних сервисов (очереди повторных попыток, дед-леттеры).

Этот процесс обеспечивает надёжность, масштабируемость и поддерживаемость сервиса, а также позволяет безопасно развивать дополнительные функции.
